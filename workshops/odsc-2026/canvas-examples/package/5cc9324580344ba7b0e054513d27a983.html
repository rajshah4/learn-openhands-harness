## Summary

**Root cause** — a read-modify-write race across an `await` boundary in `AsyncCounter.increment()`:

```python
current = self.value      # every task reads 0 before any writes
await asyncio.sleep(0)    # yields to the event loop here
self.value = current + 1  # all write 0 + 1 = 1
```

All 50 coroutines read `current = 0` during the `sleep(0)` yield, so the final value collapsed to `1` instead of `50`.

**Fix** — removed the `await asyncio.sleep(0)` between the read and write, making the increment atomic:

```python
async def increment(self) -> None:
    await asyncio.sleep(WORK_DELAY_SECONDS)  # simulated work, still concurrent
    self.value += 1                           # atomic: no await between read/write
```

Key design point: I kept `await asyncio.sleep(WORK_DELAY_SECONDS)` as-is because that's the *simulated concurrent work* — it must overlap. The elapsed-time test (`< 0.08s` for 30 jobs) rules out the naive approach of wrapping the whole body in an `asyncio.Lock`, which would serialize the sleeps to `30 × 0.005 = 0.15s`. The correct fix is to keep the work concurrent and make only the tiny critical section (the increment itself) atomic, which is free in a single-threaded cooperative event loop as long as there's no `await` between read and write.
